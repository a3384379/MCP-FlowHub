# 报告证据校验补充契约

本文件补充 `incident-report/v1` 的可执行索引格式，对应 F10 和 AGT-13。依据是原始设计 `docs/02_协议接口与数据设计.md` 第 9 节、`docs/04_测试验收与云端交付.md` 的 AGT-13，以及 `templates/incident-report.md`；原始设计文件保持不变。仓库中不存在另一个 `contracts/report-contract.md`。

宿主提交实际 `reportMarkdown` 与 `evidenceRefs`。报告中的每个 artifact ID 都必须属于当前运行、未过期，并出现在 `evidenceRefs`；该数组不得重复。固定的“证据索引”章节只能出现一次，每个引用必须恰有一条索引记录。正文引用和正文中偶然出现的哈希不能替代索引记录。

十个必需章节与证据索引共用同一个可见 ATX 标题解析器：支持一至六级 `#` 标题、最多三个前导空格、CRLF、末尾以空格分隔的闭合 `#`，以及章节名称后的中英文括号说明。反引号或波浪号代码围栏、HTML 注释内的标题不计为章节；围栏内的注释标记不会影响围栏外的标题。实际保存的原文须通过校验，业务内容不自动替换，不能仅将代码示例中的章节清单认定为完整报告。

支持以下索引记录格式，与 Hub 模板已生成的格式兼容：

```text
- artifactId / sha256 / 123 bytes
- artifactId / sha256
```

这里 `artifactId` 使用服务实际返回的 ID，`sha256` 使用服务返回的 64 位十六进制摘要；可加 `sha256:` 前缀，十六进制大小写均可。ID 和摘要可使用单个 Markdown 行内代码反引号。字节数可省略；提供时必须是匹配实际 UTF-8 内容的非负安全整数，可加 `bytes` 后缀。

也支持列顺序为 `artifactId | sha256 | byteLength` 的 Markdown 表格，最后一列可省略。行内不能插入来源节点等额外列；这些说明可放在对应的正文证据章节。代码围栏内的记录不算索引记录。

索引摘要必须与 Hub 存储的同一条证据的实际内容、摘要元数据一致。提供字节数时也必须匹配。正文中其他明确使用 `artifactId / sha256`、`artifactId / sha256 / byteLength` 或相同表格格式的声明复用同一解析器，校验全部已提供字段，不能与索引冲突；错误或格式无效的第三段字节数都会被拒绝。斜杠格式声明可用句号、分号、逗号或右括号等自然标点结束。重复索引即使摘要相同也拒绝，避免一条 ID 对应多个声明。

兼容变化：过去仅在十个章节中提及有效 ID 的宿主报告可能被接受，即使没有索引摘要，错误摘要也未被比较。现在该提交返回 `ARTIFACT_INVALID`，保留原检查点供宿主修正后重新提交；不会创建已验证的 MD/HTML 报告产物。旧自动化正例已补充真实索引摘要。Hub 模板既有的 `ID / SHA / bytes` 输出继续适用。

`contentStored` 仍仅表示实际报告字节已存储；`formatValidated` 表示章节格式通过；`evidenceReferencesValidated` 表示当前运行证据、完整索引与声明的摘要和可选字节数通过校验。`skillExecution=host_reported` 仅是宿主声明，`factualReview=not_performed` 不会因引用或哈希匹配而改变。校验不证明 Skill 实际执行，也不证明报告结论属实。

引擎调用纯校验 helper 时必须只传入当前运行已授权且未过期的产物。摘要比较不能取代该运行和授权过滤。
