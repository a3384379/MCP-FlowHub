# MCP FlowHub 1.0：Codex 云端开发任务书

版本：1.0 设计基线 · 日期：2026-10-29 · 状态：开发计划与提示词，尚未创建实际产品代码或 GitHub 仓库。

本文件供你把设计包放入 GitHub 后，分阶段交给 Codex 云端实现。它不表示已创建分支、PR、CI、Release 或可运行安装包。文中脚本名、目录和命令均为待实现约定，必须由实现提交和实际执行结果确认，不能现在直接当成已存在的命令使用。

## 1. 使用顺序与不可跳过的门禁

1. 由你创建或选定获准的 GitHub 仓库，将设计文档、契约、合成示例和 UI 原型纳入版本管理；不要上传公司项目、内部 MCP 配置或凭据。
2. 连接 Codex 云端的该仓库，只授予完成开发所需权限；依赖安装仅发生在获准的开发/CI 环境。
3. 先运行“初始化提示词”，再执行 S0。每次一个边界明确的 PR；完成审查后再发下一阶段任务，不使用“一次实现全部系统”的大提示词。
4. S0 必须得到两份不同证据：云端真实构建/协议测试结果，以及公司批准设备的离线包运行核验记录。后者未完成时记为 `BLOCKED`，不能由云端模拟通过代替。
5. 公司 IT 不允许的运行方式、透明加密兼容问题、企业数据使用权限是停止条件。仅可采用 IT 批准的部署替代路径，不能关闭、绕过、解密或搬运受控文件来继续。
6. S1–S5 各自合并门禁满足后逐步推进；S5 只生成候选发布。真实生产及试运行只读联调通过前，不声称全部功能已在公司环境验证。

阶段提示词引用的测试 ID 可能横跨多个层次：当前阶段只交付自己负责的领域/协议断言，未进入阶段的完整 E2E 必须标为待验证并注明归属阶段，不能为了凑齐通过率假实现后续功能。例如 S2 可验证检查点领域状态，真正的 Codex 引导报告闭环由 S4 验收；S5 汇总全部 100 项实际结果。

本项目不要求额外的 LLM API Key。云端使用合成数据和 Mock MCP；公司真实工具、端点、凭据和查询模板只在获准的本地环境登记。Hub 本地部署不等于模型处理的数据不出网，Codex 接收生产证据也须获公司批准。

## 2. 建议的仓库结构

下面是实施目录约定，不代表设计包已包含这些应用。采用其他布局必须先提出小范围变更记录，不能同时维护两套引擎。

| 路径 | 职责 |
|---|---|
| `AGENTS.md` | 采用第 3 节模板并补充实际命令 |
| `apps/daemon/` | 唯一守护进程入口、生命周期、组合根 |
| `apps/mcp-bridge/` | STDIO 薄桥；只转发，不持久化和调度 |
| `apps/web/` | React 管理 UI、画布、运行台及审批界面 |
| `packages/contracts/` | 领域 DTO、状态、错误码、运行期 Schema |
| `packages/workflow-core/` | 图校验、映射、状态机、预算、调度策略 |
| `packages/persistence/` | SQLite、迁移、事务、命令去重、一致性备份 |
| `packages/mcp-connectors/` | SDK v2 下游适配、工具目录、协议代际缓存 |
| `packages/mcp-server/` | 对外固定七工具及执行身份校验 |
| `packages/admin-api/` | 管理登录、连接、发布、审批及支持包 API |
| `packages/security/` | 凭据库、权限、脱敏、输入及目标限制 |
| `packages/mock-mcps/` | 真实 MCP 协议的合成服务和故障注入 |
| `contracts/`、`examples/` | 设计契约与合成流程；与运行期契约验证一致性 |
| `tests/` | 独立单元、协议、引擎、安全、UI、打包测试 |
| `scripts/`、`.github/workflows/` | 开发任务、CI、离线包和候选发布 |
| `docs/`、`docs/evidence/` | 设计、ADR、依赖基线、脱敏验收记录 |

不要提交真实数据库、产物目录、浏览器状态、`.env`、凭据、用户配置、完整诊断包或 `node_modules`。包内依赖由 CI 按锁文件构建；公司数据目录与程序目录分开。

## 3. AGENTS.md 建议正文（模板，实施时创建）

下面内容可作为仓库根目录 `AGENTS.md` 的完整初版。它是本任务书中的模板，不表示已创建或安装宿主 Skill。

```text
# MCP FlowHub 开发约束

## 先读资料
先完整阅读 docs/01_产品与架构设计.md、docs/02_协议接口与数据设计.md、
docs/04_测试验收与云端交付.md，再读当前阶段相关 UI 说明、契约和示例。
若文档、代码、Schema 有冲突，列出冲突并停止冲突部分，不自行放宽安全边界。
变更前检查工作区；保留已有用户改动。不得重置、清理或覆盖无关文件。

## 固定架构
只有一个 Hub MCP 服务，工具固定为 workflow_search、workflow_get、workflow_start、
workflow_advance、workflow_status、workflow_cancel、artifact_read。
新增工作流只新增数据，不生成服务、Tool 或任意工具透传接口。
flowhub serve 是唯一 daemon；STDIO 薄桥只转发，不写 SQLite、不启动第二引擎。
V1.0 只支持串行与互斥条件分支；并行分叉、循环及回边必须拒绝发布。
guided 由宿主推进 WAITING_AGENT；auto 只接受确定性节点，不暗中调用模型 API。
宿主 Skill 只能交接契约，不能声称 MCP 能直接执行任意已安装 Skill。

## 环境与权限
云端仅使用合成数据和真实协议 Mock，不索要或上传企业端点、凭据、日志和表结构。
环境/连接/资源/模板固定在已发布版本，用户输入、Agent 输出和日志不得覆盖。
环境档案仅使用 UNVERIFIED、MOCK_VERIFIED、BINDING_VERIFIED、REVOKED。
生产只读来自真实账号及可信服务端权限，不以提示词/readOnlyHint/SQL前缀代替。
人工批准仅通过独立管理 UI 会话；MCP execution token 不能批准、解锁或改配置。
不增加任意 shell、eval、JS 节点；STDIO 使用明确 executable/args 与 shell:false。
不绕过公司加密、安全软件、网络限制、审批或其他权限边界。

## 可靠性与依赖
Node.js 24 为目标基线；S0 锁定补丁版、SDK v2 和全部依赖，保留 lockfile。
官方 SDK v2 负责现代/legacy 协议适配；不能自行写线协议转换桥。
正常调用使用已验证的协议代际；401/403 不得通过降级、匿名重试或换凭据绕过。
SQLite WAL、唯一 daemon、事务/CAS、命令幂等；网络调用不放进长数据库事务。
OUTCOME_UNKNOWN 是原运行终态，人工复核后新建 run，不篡改原记录为成功。
密钥库使用口令派生与认证加密，重启锁定；不得保存明文主密钥。
所有下游参数依真实 inputSchema 适配，不硬编码公司连接或臆造工具字段。
新增依赖需记录用途、锁定版本、许可证和 Windows 兼容性；不照搬受限项目代码。

## 测试与交付
每个 PR 关联 docs/04 的测试 ID，修复先加失败用例，再实现，再跑回归。
必须有独立协议/策略断言和负向对照，不用 FlowHub 自己报告成功证明自己正确。
命令先确认存在再执行；缺少脚本如实报告，不能伪造命令、退出码或日志。
实际记录 PASS、FAIL、BLOCKED、SKIPPED、UNVERIFIED；未执行不写为通过。
外部 PR 无真实 Secret；禁止高权限工作流执行未信任 PR 代码。
Windows 与 Ubuntu 分别验证；发布包不能依赖公司电脑临时 npm install。
只改当前任务授权目录；额外依赖、重构、发布、权限扩大先说明并取得授权。
结束时列出修改、命令/退出码、证据路径、未验证项、风险和下一阶段准入结论。
```

## 4. 脚本与证据命名约定

S0 确认包管理器后，在根 `package.json` 实现以下任务名。表中名称现在只是约定；具体执行前查看仓库脚本，不假装它们已经可运行。

| 拟定任务名 | 约定输出 |
|---|---|
| `check` | 类型、格式、Schema 与锁文件一致性 |
| `test:unit`、`test:protocol` | 单元及现代/legacy × STDIO/HTTP 矩阵 |
| `test:engine`、`test:security` | 状态、幂等、恢复、环境与权限负例 |
| `test:ui`、`test:package` | 浏览器关键路径、离线包解压启动冒烟 |
| `build`、`package:windows` | 构建产物及 Windows 原生离线 ZIP |
| `verify:release` | 包哈希、源码 SHA、SBOM、许可证与无敏感配置检查 |

证据建议为 `docs/evidence/S<N>-<日期>-<短SHA>.md`，记录环境、基线/结果 SHA、实际命令与退出码、用例结果、合成场景种子、未验证项。CI 大型输出保存在访问范围适当的 CI artifact，不把企业证据写入公开仓库。尚无真实测试结果时建立空模板并标明“待执行”，不能生成假 PASS。

## 10. S4：Codex 引导与报告证据提示词

```text
只实现 S4 宿主协作闭环。输入：S3、七工具契约、报告契约、双环境合成示例。
目标：实现 WAITING_AGENT 的结构化任务、短期 checkpoint token、revision 与原子消费。
一次运行一个活跃 Agent 检查点；返回本 run 可访问证据和已执行/跳过节点状态。
```

## 14. 每个阶段的最终交接格式

按固定顺序交付：本阶段实际实现 → 关联测试 ID → 实际命令和结果 → 产物/证据路径 → 未实现/未验证项 → 风险 → 准入结论。准入结论只取“可进入下一阶段”“有条件进入（列明接受人和限制）”“阻塞”。S0 公司授权及离线运行门禁、生产环境验证和 P0 安全失败不能用一般性“有条件接受”跳过。

本任务书提供可复制的实施指令，不承诺 Codex 一次完成全部开发，也不将文档、原型、Mock 或模拟通过视为已实现的生产产品。
