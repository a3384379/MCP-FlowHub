## 新旧流程

旧：日志 MCP → Agent → 人工审批 → 数据库 MCP → 结果分析 → 报告，业务结果存在遮挡展示值和加密原值两套表示。

新：日志 MCP → Agent → 条件 → 数据库 MCP（允许跳过）→ 结果分析 → 报告。Agent/Skill 提交后自动继续；有效绑定的数据库工具不需前置决定。业务 JSON、类型及文本按原值保存与映射。对 Codex 仍是一个 MCP Server、固定七工具。

## 删除与保留边界

不再生成审批 ID、审批动作 hash、批准对象或审批等待状态；不再注册决定路由。保留 `approval`/旧状态字符串的代码仅用于识别与迁移历史数据。SQLite 历史审批表及清理逻辑继续保留，以维持 v1 迁移校验和及历史生命周期；没有新增决定消费者。

原通用业务 redact() 与 Vault.redact() 已删除。邮箱/手机号自动替换规则已删除。凭据保护移到专用 `security/diagnostics.ts`，仅由连接目录、绑定影响和校验错误边界使用；引擎的业务数据和报告不调用它。连接登记时可执行文件授权属于配置安全，未增加运行审批。

Schema、图结构、支配关系、参数引用、固定环境、工具与模板、发布版本和实际连接修订检查均保留。宿主不能覆盖这些配置。HTML 转义及证据哈希校验保留；实际 Markdown 可按原字节读取。

## 迁移结果

合成测试证实：旧节点唯一 next 出口可自动移除并重连；新建独立 ID 的未发布草稿，原草稿和发布快照不变；生成一致性 SQLite 备份。多出口、循环和决定输出依赖拒绝猜测，返回 MIGRATION_MANUAL_REQUIRED。

重启时先备份旧活跃运行，未派发运行转 CANCELLED，已有 dispatch 转 OUTCOME_UNKNOWN，并终结对应尝试；原因 LEGACY_WORKFLOW_RETIRED，不重放调用。历史结果与报告保留，受原保留策略管理。旧 operationalOutputs 密文仍按原 AAD 解密、口令轮换、映射和读取；锁定时明确标记不可用。过去已丢失的业务原值不能伪造还原。

参见 [迁移操作](MIGRATION_AUTOMATION.md)。此轮仅处理合成夹具，未读取或迁移真实业务库。
