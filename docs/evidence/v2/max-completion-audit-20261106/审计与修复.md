## 反例与修复

| 级别/编号 | 原实际行为 | 修复后的实际行为 |
| --- | --- | --- |
| P1 MAX-01 | 首例远端超时产生 OUTCOME_UNKNOWN，匹配错误断言后仍派发次例，整体 SUCCEEDED | 只派发一次；首例失败，余例 NOT_RUN，整体失败；取消/中断仍保留未知标记，原键与重建不重放 |
| P1 MAX-02 | 字面模型 Key 被拒，Unicode 转义的相同 Key 解码后却保存到套件 | 解析后递归检查键和值；受管认证值整体拒绝，0 套件副本；上下文在任务入库与派发前检查，正常业务值保留 |
| P2 MAX-03 | 收到 MCP isError 响应也误标 outcomeUnknown | 明确记录已知响应；预期错误仍可通过并运行后例，安全配置的有界重试保持 |
| P2 MAX-04 | 一次生成的 modelCalls=1，实际 HTTP 却可重试 3 次 | AI 内部 maxAttempts=1；429 后失败且重放无新请求，普通助手默认最多 3 次且可取消 |
| P2 MAX-05 | 缺 nodeId、幽灵节点或路径错误被变成 null，与 expected:null 比较通过 | 共用 Schema 加必需字段/类型；提交与运行前校验现有节点及种类；运行缺值为 evaluated:false 的失败，合法 null 仍可通过 |
| P2 MAX-06 | 51 个新终态任务把旧活动生成挤出最近 50 条列表，页面无法恢复/取消 | 活动 QUEUED/RUNNING 优先；保留 owner、过期和只返回元数据限制 |
| P2 MAX-07 | A 套件丢回执后，B 的相同请求体复用 A 的键，永久 409 | 签名绑定 method、完整 URL 路径和业务体；同目标保留原键，跨套件请求分离 |
| P2 MAX-08 | 生成成功后的迟到套件 GET 关闭编辑器并覆盖 dirty JSON | 等待套件回执保持锁定；dirty 不自动采用新套件，可明确切换、暂存和恢复，恢复保持原 CAS 修订 |
| P2 MAX-09 | 外部更新套件后服务端 stale=true，终态页面仍显示旧成功且无过期标记 | 周期/焦点只读回读套件和任务；显示基线过期，不重复 POST；旧 GET 不倒退新修订 |
| P2 MAX-10 | 合法 $ref sibling 类型变化被静默跳过，changes=[]/truncated=false | 分别记录引用与 sibling 约束位置；type/required/限制变化能定位，循环/外部引用或预算不全明确标 truncated |
| P2 MAX-11 | 手工保存 AI 用例后丢失 generationRef 和初始来源 | generationSource 保留初始来源、revisionSources 保留逐修订元数据；generatedBy 表示当前提交方式，不复制旧用例正文 |
| P2 MAX-12 | Mock 的 trace 数称为“真实工具调用” | 明确显示“模拟工具调用”；实际本地 SDK 服务计数证明模拟轨迹 1、真实 tools/call 0 |

认证保护只针对 Vault 已知受管认证值，拒绝整个上下文/提案，不重写业务原值；普通配置、业务 token/password 字段等未被规则自动脱敏。旧套件不会被静默改写：无效断言会在运行前被拒绝，需明确编辑；缺失来源只在后续编辑时补充可知历史，不编造以前已丢失的记录。复杂 Schema 差异是有界结构诊断，不是合并后的完整有效 Schema 证明。
