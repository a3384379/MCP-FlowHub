- `CapabilityRegistry.context:44-52` 区分省略与显式自动查找；保留原目标 ID / CAS。身份变化返回 typed `CONTEXT_IDENTITY_CHANGED`，不会静默修改其他上下文。

## D08：刷新、保存和凭据激活各有归属

- 同一实体 snapshot 刷新只取消过时读取，不清空凭据选择、pending 状态或成功回执；来源变化仍保留开始配置时的 sourceId / revision，提交由后端 CAS 拒绝。
- 首轮独立真实产品目标 UI 4/4，包含上述 D07 两项，以及 D08 保存中刷新后的真实 200、connection.secretRef、成功提示和来源变化旧 revision 的 409 / 不新增连接。
- max 私有补审另发现 D08 的自动/手动凭据加载反向回包漏洞：初始 GET /secrets #0 等待时可再次显式激活 #1；#1 先完成并选择 ref 后，#0 晚到会清空选择。发现时未用已有 4 项 PASS 关闭 D08；原始 before 文本与旧 bundle 保留。
- 后续修复为凭据激活增加独立 `credentialActivation` 代次。`DiscoveryDetail.tsx:101-116` 对成功和错误都校验当前导航与激活；snapshot 不取消有效激活，导航/卸载使旧激活失效。
- 用相同精确 React 组件 harness 重放：逆序成功回包保留 ref；旧激活错误不显示、不清 ref；初始加载跨 snapshot 只产生一次 secrets 请求；A→B 导航后 A 晚回不覆盖 B。四个边界全部通过。
- 最新 source/bundle 上再独立执行真实产品复合 D08 用例 1/1：逆序 secrets → 保存 pending 时刷新 → 真实 200、准确 secretRef、完整成功提示。此为同一用例的修复后重跑，不算额外独立用例数。
