## 审计范围与结论

核对当前已实施的“三组、七个同级直达入口”，以及用户随后报告的模型 `CREDENTIAL_LOCKED`。工作流画布仍是工作流下级页面，AI 助手仍为全局悬浮入口，未恢复重复的一级菜单。模型配置保持一步直达。本轮没有将导航改成后续原型中的“设置合并”变体，两者须分别核对。

原实现常规路由、唯一选中项、面包屑、未保存草稿离开提示、移动抽屉焦点控制均通过。补充实际缩放及锁定场景后确认以下问题并修复。

| 问题 | 复现及影响 | 修改与验证 |
| --- | --- | --- |
| P2 移动导航未使用实际可视区域 | 390×844 下 2 倍缩放，实际区域为 195×422，关闭按钮右侧到 247，系统设置底部到 548.8；需要额外平移寻找操作 | 抽屉与悬浮助手共用 visualViewport hook，监听 resize/scroll；宽高、位置随可视区调整，极窄时压缩品牌和账户区，菜单独立滚动。现有响应式用例新增 2/3 倍缩放和关闭/系统设置/退出边界断言 |

## 实际代码行为

- `shared/useVaultState.ts` 仅查询锁定状态，不读取 Key。页面聚焦、可见性恢复、配置凭据变更时重新读取；卸载/新请求使旧回执失效。助手关闭时不新增状态查询；遇到新的锁定失败重新查询真实状态，不把历史失败当作当前仍锁定。
- `settings/VaultNotice.tsx` 共用说明和操作，口令仍只进入既有本机专用弹窗；解锁成功事件更新当前页面，聊天输入和模型草稿保持。
- 未产生正文和工具回执的锁定失败轮次提供“重新提问”，只填回原问题，需用户再次发送；已有回执的轮次保持原只读续答语义，避免重复业务写入。
- 兼容服务输入新 Key 后仍可查询目录；读取已保存 Key、保存与探测先要求解锁。原模型服务协议、Base URL 归一化、官方模型目录查询和 API Key 保管路径保持。
- 移动导航使用共享可视区边界；原助手 viewport 导出保持兼容。无新增依赖、DDL、工具、业务脱敏或审批流程。
