# MCP 连接配置与凭据库改造

日期：2026-11-01。基线：`1721420bc43a0efeac088abbe9580ec34837a4e3`，分支 `feat/flowhub-v2`。使用现有 checkout，不另建应用。Node 24.19.0 / npm 11.9.0 / macOS arm64。

## 实际交付

- 发现页的“配置凭据”改为“连接配置”。同一抽屉将普通配置、认证凭据、用途待确认分组；可使用来源内联值、填写新值、选择已有引用，并在原表单内解锁本地库，保留填写内容。
- `CBM_ALLOWED_ROOT` 显示为目录范围，`CBM_LOG_LEVEL` 显示为日志级别并提供可选建议；字段附官方配置说明。仅识别这两个已核对声明，其他未知变量不猜测；HTTP 认证声明优先于普通配置声明。
- “接入设置 → 配置与凭据库”增加明确新增入口、用途分类与真实使用位置。模型 Key 从 MCP 候选列表排除；后端在发现配置和手动连接创建/更新两条路径同时拒绝模型引用。
- 新建项与引用通过同一事务和幂等命令保存；失效来源、上下文变更、用途不匹配或部分参数失败均回滚，不留下孤立新条目。断网时冻结原请求供重试；明确冲突保留输入，不自动改写提交基线。
- 保存与检测分阶段显示。单服务检测通过官方 SDK 读取协议与工具目录，不扫描无关服务、不执行 `tools/call`、不新建资源绑定。检测失败保留已保存配置，可单独重试；关闭服务时取消并等待检测，取消后的迟到成功不能发布目录。
- 保留所有旧凭据 ID、密文和连接记录，无 DDL 变更。旧用途通过实际模型/连接引用补充显示，不按 label 猜测；不确定项保持待确认。新普通配置同样加密保存，且不会因值恰好为 `info` 等文本而误判普通目录内容为认证泄露；真实认证/模型引用始终保留保护。
- 新增仅本地管理接口 `GET .../:id/configuration` 与 `POST .../:id/detect`；扩展原保存接口，旧请求格式继续兼容。固定 21 个 MCP 工具保持不变。未恢复人工审批或业务自动脱敏。

发现字段元数据：`packages/host-discovery/src/connection-fields.ts`；用途与真实引用：`packages/security/src/credential-metadata.ts`；加密与诊断匹配：`packages/security/src/index.ts`；原子保存和单服务检测：`packages/capability-registry/src/index.ts`；管理接口：`packages/admin-api/src/{index,v2}.ts`。

## 浏览器人工路径核验

通过 Playwright CLI、独立 Chrome for Testing 临时会话操作真实页面和隔离 daemon：

1. 仅配置发现识别两项普通 CBM 配置和独立认证来源，模型 Key 不出现在连接选择中。
2. 在库锁定时填写日志级别 `info`，原位解锁后值仍保留。
3. 模拟断网后点击保存并检测，显示“保存结果尚未确认”，保留值和原幂等请求；恢复网络后重试成功，真实 SDK 读取到 4 个合成工具。
4. 从管理库新增合成认证项，自动切换到 MCP 认证分类，列表不显示保存值。库中可区分模型 Key、MCP 普通配置和 MCP 认证，且展示实际引用数量。最终版本从连接表单跳转后，自动滚动并聚焦 `credential-library`，在 806 像素高视口中顶边位于 107.83 像素，见 `library-navigation.png`。
5. 390 与 320 像素视口中，文档宽度和抽屉宽度均等于视口，无横向溢出。截图经过人工查看：`desktop-configuration.png`、`mobile-configuration.png`、`network-retry.png`、`credential-library.png`。

预期控制台错误仅包括未登录 401 和主动断网的 fetch 失败；不将这两项当作意外应用错误。浏览器仅使用合成密钥与临时目录，未操作个人 Chrome。
