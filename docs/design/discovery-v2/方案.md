# Codex 发现页改造方案与设计图

2026-10-31 · 设计提案 · 核对基线 `feat/flowhub-v2@d0c0699`。

设计阶段交付修改方案、可点击原型和页面设计图。用户随后批准开发，实际改动与验证见[实施记录](实施记录.md)。原型全部使用合成示例，不代表本机实际已安装、已连接或可调用的能力。此前未提交的助手审计材料保持原样。

下文“待实现”等表述保留设计时状态；当前实现与验收以实施记录为准。

## 1. 改造目标

让用户在一个页面回答：**我有什么、各自能做什么、它们是什么关系、现在能在哪里用、接下来做什么。**

建议保留导航入口“Codex 发现”，页面标题改为“Codex 能力发现”。页面顶部用一句话说明：读取当前本机 Codex 的 MCP 配置、已安装插件与 Skills，查看能力并用于 FlowHub 或 Codex 流程。

当前源码 `apps/web/src/features/discovery/DiscoveryPage.tsx` 存在以下信息组织问题：

| 当前表现 | 改造 |
|---|---|
| 来源和组件混排，`kind`、`executor`、错误码等原始值直接展示 | 分成 MCP 服务、Skills 技能、插件与关系、需处理四个入口；内部枚举映射中文 |
| 所有能力统一称为“MCP 能力目录”，Skill 和 MCP Tool 平铺 | MCP 服务下展开工具；Skill 单独成项；插件仅作为组件集合 |
| 现有 Skill/Tool 描述已有读取，但列表没有呈现用途 | 每行固定展示中文名称、原始名称、一句话用途、来源、使用位置及状态 |
| 详情主要是一整块 JSON | 详情抽屉先显示用途、输入输出、工具、关系和使用条件，原始 JSON 按需展开 |
| 默认页面需要理解上下文、执行器、修订、固定环境等实现概念 | 上下文合并成一条摘要；高级发现设置折叠；环境只在实际导入时出现 |
| 只知道导入按钮，不知道为何可用或不可用 | 状态旁给出原因与对应动作；区分目录读取、导入和真实执行验证 |
| 中文展示缺少独立契约 | 增加显示元数据层，由 Codex 同步中文说明，保留原文和来源版本 |

## 2. 分类与关系规则

官方 OpenAI 文档将插件定义为可包含 Skills、MCP 或二者的包；Skill 是工作方法和指令，也可以独立工作。因此不能把所有 Skill 强行放到 MCP 下面。[插件架构](https://developers.openai.com/plugins/concepts/plugins)、[Skills 与依赖声明](https://developers.openai.com/plugins/build/skills)。

```text
插件：研发协作
├─ 包含 → MCP：GitHub
│          ├─ 工具：search_repositories
│          └─ 工具：get_pull_request
├─ 包含 → Skill：代码审查
└─ 包含 → Skill：整理变更日志

Skill：代码审查 ── 声明依赖 → GitHub MCP
Skill：流程报告 ── 独立技能 / 未声明 MCP 依赖
```

| 关系 | 依据 | 页面文案 |
|---|---|---|
| 插件包含 MCP / Skill | 安装清单及其解析出的路径；当前 `locator.plugin`、`component.parent` | “所属插件：研发协作 · 清单已确认” |
| MCP 包含 Tool | 同一次真实目录同步的服务器身份和工具目录；宿主工具需唯一匹配 | “GitHub → 搜索仓库” |
| Skill 声明依赖 MCP | `agents/openai.yaml` 等受支持的结构化依赖声明 | “声明依赖：GitHub · 已匹配当前配置” |
| Skill 说明中提及 MCP | 原始说明的明确引用，且有对应证据位置 | “说明中提及”，不当作可执行依赖或所有权 |
| 来源无法唯一对应 | 无声明、同名多来源、路径不明或格式不支持 | “未声明 MCP 依赖”或“关系待确认”，不猜测 |

中文译文不能创建关系；名称相似、同一目录、同一插件不等于 Skill 归属于 MCP。独立技能无依赖是正常状态。当前发现器尚未读取结构化 Skill 依赖，也未完整提取插件说明，属于后续真实实现范围。

## 3. 页面布局

采用现有冰蓝白配色、系统中文字体，借鉴常见扩展管理器的“分类列表＋详情抽屉”，不再采用长表单和原始数据墙。1440px 桌面导航约208px，主内容留白28px，详情抽屉宽520px；小屏抽屉铺满可用宽度。

### 总览 / MCP 服务

- 页头：标题、用途说明、“重新扫描”“同步工具目录”。扫描按钮只读配置与元信息；同步目录会连接服务读取工具定义，不调用业务工具。按钮下明确最后扫描、覆盖范围和时间。
- 四个摘要：MCP 服务数、Skills 数、已安装插件数、需处理项数。失败/未扫描显示“未知”，不显示0；统计基于同一上下文快照，不能用当前分页数量冒充总数。
- 类型页签：MCP 服务 / Skills 技能 / 插件与关系 / 需处理。点击摘要可进入对应页签。
- 简短概念提示：MCP 提供工具，Skill 指导如何做，插件打包它们。可收起。
- 搜索：同时匹配中文用途、中文名、原始名和插件名；在服务端按类型、来源、使用位置、状态过滤，支持分页。
- 每行：类型图标、中文名＋原始名、用途、所属插件/独立来源、调用位置、目录状态、工具数量、详情入口。
- 默认不显示路径、内部UUID、hash和Schema。保留高级详情，方便定位问题。

### MCP 详情

先展示“能做什么”和状态，然后分为“工具目录 / 相关 Skills / 来源信息”。工具项显示中文名、原始调用名、用途、参数及结果说明；仅使用目录真实提供的描述和Schema。没有说明就写“来源未提供”，不靠翻译补造能力。

相关 Skills 分别标明“同一插件”“声明依赖”“说明中提及”，同一插件的所有 Skill 不自动变成该 MCP 的依赖。`codex_host` 对应“仅 Codex 调用”，按钮“用于 Codex 流程”；`hub_direct` 对应“可导入 FlowHub”，导入后仍需按现有流程验证连接与绑定。FlowHub 自身禁止递归导入。

### Skill 详情

显示“适合什么时候用、需要提供什么、会得到什么、需要哪些 MCP、在哪里运行”。中文介绍仅为阅读辅助；真正执行仍使用原始 Skill 内容、身份、版本和既有宿主约束。完整 `SKILL.md` 放在“原始技能说明”，中文摘要不替代原始指令。

### 插件与关系

每个插件按清单展开 MCP 与 Skills 两组，清晰显示组件数量和“仅技能插件”等形态。选择 Skill 时可查看其声明依赖的 MCP；跨插件依赖单独连线，不改变父子关系。

关系图优先使用易读的分组树，不把所有来源画成杂乱的全量网络图。未安装的市场推荐不进入“已安装插件”统计；解析失败的来源出现在“需处理”，不伪装成已安装且已可用的插件。

### 需处理与导入

| 状态 | 文案 / 动作 |
|---|---|
| 未扫描 / 范围未覆盖 | “数量未知”“扫描配置” / “查看读取范围” |
| 已读配置，未读工具目录 | “待同步工具” / “同步工具目录” |
| 缺凭据 | “需要配置连接凭据” / 专用Vault配置入口 |
| 禁用 | “已停用”并说明来自Codex配置；本页不静默修改源文件 |
| 宿主专用 | “仅 Codex 调用” / “用于 Codex 流程” |
| 已导入但未验证 | “已导入 · 未验证” / “前往 MCP 工具库验证” |
| 来源变更 / 漂移 | “来源已更新，需要重新同步”，保留历史引用与旧说明的过期状态 |
| 插件格式不支持 / 歧义 | 中文原因＋原始错误码＋具体来源；可重试，不阻塞其他结果 |

导入操作仍沿用固定环境、锁定参数、来源修订与幂等；默认测试环境，不因页面重构放宽现有边界。不新增人工审批。

## 4. Codex 上传时中文化

“上传”在此指 Codex 将发现结果和中文说明同步给本机 FlowHub daemon，不向云端上传本机配置。读取配置本身不启动翻译任务。

```text
本机只读发现 → 保存原始元数据及来源指纹 → 立即可浏览
                                           ↓
Codex 同步任务：读取缺失/过期说明 → 翻译与摘要 → 提交中文显示元数据
                                           ↓
daemon 校验身份、来源及版本 → 保存显示层 → 页面显示中文＋原名
```

- **Codex 路径**：用户让 Codex 扫描/同步能力时，任务包括中文整理并提交。复用现有 Codex，不要求再配置 FlowHub 模型 Key。来源无说明时如实标记，不能杜撰用途。
- **网页自动扫描**：立即返回原始结果与已存在的有效译文，不自动启动 Codex、不要求Key。缺译文标“待中文整理”，提供“复制 Codex 整理任务”，用户可交给现有 Codex 会话。中文整理与连接问题分别计数。
- **已有数据补齐**：只提交缺失/过期条目；有效译文复用；支持中英文切换、查看原文和手工纠正。用户手工文案不能被后续自动译文覆盖。
- **中文范围**：插件/MCP/Skill显示名称、一句话用途、介绍、使用场景、工具与参数的说明。保留品牌和原始名称。超长文档做中文摘要，完整中文译文以后按需提供。
- **原值保留**：不翻译tool调用名、Skill身份、参数键、枚举值、Schema结构、路径、ID、示例中的真实业务值；不改Codex配置或 `SKILL.md`。这是新增阅读辅助层，不是业务自动脱敏。
- **信任边界**：源说明按数据处理，不执行其指令；中文说明按纯文本/安全Markdown呈现，不引入HTML执行或任意命令。

### 建议数据契约（待实现）

新增 `discovery_presentations` 及可追溯关系投影，顺序追加迁移，不改旧DDL/checksum。显示元数据按 `contextId + entityKind + stableEntityKey + sourceFingerprint + locale` 绑定，不能用中文名作为身份。

```json
{
  "entityKind": "skill",
  "entityKey": "<daemon返回的稳定标识>",
  "expectedSourceRevision": 3,
  "sourceFingerprint": "<daemon返回的原文指纹>",
  "locale": "zh-CN",
  "displayName": "代码审查",
  "summary": "检查拉取请求的改动并整理可操作的问题。",
  "description": "<基于来源的中文介绍>",
  "useCases": ["检查一次拉取请求"],
  "evidenceRefs": ["<已发现描述或文档的受限引用>"],
  "authorship": "codex"
}
```

服务端派生 `original / localized / pending / stale / manually_edited` 状态；不相信客户端声明自己已经验证。MCP缺少服务级介绍时可以依据工具目录形成摘要，但须标“根据工具目录整理”，记录用到的工具修订，不能伪装成厂商原文。参数说明按Schema JSON Pointer关联，key和类型不变。

为满足“Codex上传时带中文”且保持固定21工具，建议对已有 `host_scan` 做兼容扩展：旧参数或 `action=scan` 保持现有扫描行为；新增严格区分的 `action=submit_descriptions`，只允许向已发现、当前owner可访问的上下文提交有界中文显示元数据。与扫描参数互斥，不触发新扫描，不安装插件、不导入连接或执行工具。更新MCP契约、管理API和文档；不新增任意透传工具。

提交使用上下文修订、条目来源修订/指纹和幂等key；同一请求先校验再事务写入，过期/越权/不存在条目返回具体错误，不能靠翻译注册新能力。Web手工修正文案通过相同daemon服务保存。自动文案遇手工版本返回冲突并保留手工值。精确字段和限额在实现前形成Schema（建议单批≤50条、总大小≤128KiB，文本字段长度和引用数量单独限制）。

当前接口**没有**中文说明提交能力；这部分必须真实扩展后端，不能在前端塞一份中文词典后宣称完成。源变化后旧译文标过期；已发布工作流快照、绑定与调用名不随显示文案变更。

## 5. 实施顺序

| 阶段 | 实际改动范围 | 完成标准 |
|---|---|---|
| D1 类型与来源 | host-discovery提取清单介绍、结构化Skill依赖；registry统一entity/relationship投影和同快照统计 | 能区分MCP、Tool、Skill、插件；重复名称不合并身份；不支持来源明确报错 |
| D2 页面重构 | 拆分 DiscoveryOverview、CapabilityList、McpDetail、SkillDetail、PluginRelations、DiscoveryIssues | 列表与详情连真实接口；分页搜索过滤；未知/部分完成/禁用/宿主专用等状态准确 |
| D3 中文闭环 | 追加迁移、显示层服务、兼容扩展host_scan及管理接口、Codex同步任务说明 | Codex可提交中文，网页刷新后仍在；原名和Schema不变；无Key可发现 |
| D4 回归与验收 | 合成配置/MCP、协议Client、浏览器、数据迁移与旧数据对比 | 真实“发现→中文同步→检索→查看关系→导入→既有编排”闭环；Mock与真实宿主证据分开 |

实施时保留现有鉴权、来源修订、幂等、固定环境、Vault、宿主交接及单daemon规则。正式页面改动不影响全局悬浮助手的位置和会话状态。审计中发现的助手问题另有记录，不将本轮设计提案当作已修复。

## 6. 验收清单

1. 首次进入即可说清MCP/Skill/插件各自是什么，中文用途一眼可见；不出现默认展开JSON墙。
2. 同插件包含的MCP和Skill正确归组；依赖、同包和提及三种关系不同；独立Skill不会被随机分配给MCP。
3. 不同来源的同名对象独立；插件禁用、工具禁用、宿主唯一匹配、依赖缺失、解析不支持和分页统计有行为测试。
4. 中文同步后可用中文目标与原始英文名搜索；缺失/过期说明有状态；人工修正不被覆盖；超长/非法HTML和提示注入按数据处理。
5. 原始调用名、Schema、Skill内容、连接凭据与旧发布快照保持原值；空扫描、失败及无Key不阻塞可用结果。
6. 导入、凭据配置、用于Codex流程均接原有真实服务；已同步目录不等同执行通过。
7. 1440/1366桌面与390/320窄屏无横向溢出；Tab键可用、抽屉可Esc关闭并还焦点；错误状态有文字。
8. 执行适当的类型检查、后端/协议/浏览器回归；实际Codex中文提交和真实连接单独记录，不用设计图或fixture截图替代。

- [可点击原型](preview.html)：可切换分类、搜索、筛选、查看详情、插件关系、中英文和中文整理流程；操作只展示设计说明。
