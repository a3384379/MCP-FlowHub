# FlowHub 复用 Codex MCP 的改造方案

设计提案 · 2026-11-19 · 核对基线 `8e4d9f0`

新节点默认复用当前 Codex 上下文里已经配置、能唯一匹配且有执行契约的 MCP 工具。FlowHub 保存执行方式、工具版本、节点参数映射和运行回执。只有需要脱离 Codex 执行的节点，才在草稿中显式选用 FlowHub 直连。以「日志查询 → 数据库核对 → 报告归档」作为第一条验证链路。

## 一、执行方式

| 方式 | 适用条件 | 运行与配置 |
| --- | --- | --- |
| 由 Codex 执行 | 工具来自所选 Codex 上下文，能唯一匹配且有可验证的输入和输出契约 | 复用 Codex 的安装、配置和登录态。FlowHub 发出当前检查点，Codex 调用具名工具并回传结果。 |
| FlowHub 直连 | 有独立运行需求，服务可以通过受支持的连接方式和授权直接访问 | 先选同一服务、身份和环境下已登记的连接。需要新增时登记受支持的 HTTPS 或回环 HTTP 地址，或采用已安装服务的受支持启动方式。凭据放在本机 Vault。专用 JSON 或文本配置由 MCP 自身读取，受支持时通过已核准参数引用其路径。 |
| 执行方式待确认 | 只读取到配置，来源同名冲突，目录未同步，或具名节点的输入／输出契约缺失 | 显示具体原因及下一步操作。只有文本回执的工具先按说明型 Codex 任务使用，具名节点需要经过验证的适配契约。 |

每个发布版本锁定节点执行方式、工具身份与修订、参数映射、环境和范围。草稿可以切换执行方式，切换后重新校验并发布新版本。已有发布版本继续按各自快照执行。工作流详情汇总所有节点的宿主依赖，任何一条可达路径需要 Codex 时都标出具体节点。声明的执行环境与真实服务端授权共同约束本次取证范围。

现有目录已区分 `codex_host` 和 `hub_direct`。画布目前按能力记录的 `executor` 直接选择建节点路径，需让用户选择先于导入，且宿主路径绑定实际发现的宿主能力修订。现有服务发现与管理连接继续复用。 [能力选择器](../../../apps/web/src/features/workflows/CapabilityPicker.tsx) · [工作流执行要求](../../../packages/contracts/src/workflow-requirements.ts)

## 二、发现页

1. 页头保留当前 Codex 上下文，区分「重新扫描配置」与「同步 Codex 工具目录」。同步默认读宿主工具目录和可取得的授权状态。宿主目录读取可能初始化 Codex 已登记的服务，界面文案限定为读取工具定义。
2. 列表主列显示名称、用途、执行方式与当前可处理事项。来源路径、配置格式、修订和「待中文整理」放在详情。原有 MCP、Skills、插件关系与需处理入口延续现有用途。
3. 详情先展示「由 Codex 执行」「目录已同步」等证据。点击「用 Codex 添加到流程」，选择草稿与插入位置，默认带入对应工具及其输入、输出定义。由画布打开时沿用当前草稿和插入位置。仅发现静态配置时，入口改为「同步 Codex 工具目录」。目录已同步的状态只说明已拿到工具定义，实际调用仍取决于接力会话的可见工具和授权。
4. 同一详情保留次级入口「启用 FlowHub 直连」。用户选择后才展示现有连接或登记表单。工具目录检测通过后才显示「用直连添加到流程」。当前流程没有选用直连时，未启用、缺独立凭据等状态留在直连区。直连配置缺失只有影响用户正在设置或已选用的直连节点时才进入「需处理」。
5. 按上下文、来源与工具身份关联两种执行方式。同名工具在不同项目、服务来源或身份下各自显示。目录读不到时保留已发现内容并标记覆盖情况。只有宿主返回明确授权信息时显示「Codex 授权需恢复」。

首批开发需要调整扫描行为和列表投影。现有 `catalog` 同步会同时尝试宿主目录与符合条件的 FlowHub 直连探测。新入口应只同步宿主目录，直连检测在明确选择后对单个连接触发。复用已有上下文解析、App Server 版本适配和独立连接探测。 [宿主目录读取](../../../packages/host-discovery/src/index.ts) · [能力入库与探测](../../../packages/capability-registry/src/index.ts) · [发现页状态](../../../apps/web/src/features/discovery/shared.tsx)

## 三、节点参数

用现有的字段映射连接节点。编辑器每行显示目标字段、必填及类型、来源和样例值。来源可选「工作流输入」「上游节点输出」或「固定值」。环境、已绑定资源和受限模板由快照带入，界面显示锁定状态。样例数据来自合成夹具、手工样例或显式选中的获准历史运行。

| 合成数据库工具输入 | 来源 | 样例 |
| --- | --- | --- |
| `/orderNo` · 字符串 | 工作流输入 `/orderNo` | `DEMO-0042` |
| `/traceId` · 字符串 | 日志查询 `/traceId` | `trace_demo_0042` |
| `/limit` · 整数 | 草稿固定值，示例工具明确支持该字段 | `20` |

保存草稿时显示具体字段错误。发布前校验目标必填项、来源字段、类型和分支可达性。引用只会在另一条分支产生的字段时，提示把消费节点移到对应分支。运行时根据实际值解析一次，校验类型、授权范围和可下推的限制。字段缺失、显式 `null` 和空集合分别按工具契约处理；必填 `traceId` 缺失会停在调用之前，错误定位到该字段。

两种执行方式共用字段映射。直连由 FlowHub 将解析后的 JSON 交给连接器，宿主节点由 FlowHub 把相同的 JSON 放进 `resolvedArguments`，同时带当前工具标识和输入、输出契约版本。给 `workflow_status` 增加可选的检查点视图，新续跑流程默认只读当前参数与必要证据引用。原有状态查询继续服务运行详情与现有客户端。大段原始日志和结果保存在本次运行，默认传必要字段与证据 ID，需要详情时按现有 `artifact_read` 分页读取。 [字段映射](../../../packages/contracts/src/domain.ts) · [发布校验](../../../packages/workflow-core/src/validate.ts) · [检查点及状态](../../../packages/workflow-core/src/engine.ts)

从检查点取到以下示例参数后，Codex 直接传给快照指定的工具。日志和认证信息使用各自的已授权读取入口。

```json
{
  "orderNo": "DEMO-0042",
  "traceId": "trace_demo_0042",
  "limit": 20
}
```

## 四、回执和失败处理

FlowHub 直连使用连接器接收到的实际协议响应。Codex 节点通过现有 `workflow_advance` 回传工具结果。前者标为「FlowHub 已记录调用」，后者标为「Codex 回报」，回执校验通过时仍显示对应来源。宿主的工具调用 ID 可随回执提供，供后续对照服务审计记录。

建议先实现新版具名宿主节点的结构化提交，沿用已有运行身份、revision、检查点令牌和幂等命令账本。将工具身份、来源修订和解析参数摘要放进检查点与结构化宿主回执，作为请求对应关系的校验。供应商原始输出放在独立的结果字段，按冻结的输出 Schema 验证。真实的授权失败与调用结果未知使用具名工具的失败回执，保留原始错误和来源。这里涉及对现有工具输入 Schema 的兼容增量，工具名和原有提交格式继续可用。 [现有提交 Schema](../../../contracts/mcp-tool-inputs.schema.json) · [幂等账本](../../../packages/persistence/src/repository.ts) · [续跑技能](../../../plugins/flowhub/skills/flowhub-run/SKILL.md)

校验顺序如下。

1. 核对运行身份、当前节点、检查点令牌与有效期、运行修订。已经接收的结果可用原报文和原幂等键取回回执。认领凭证只在该检查点仍有效时重发。相同幂等键搭配不同报文会触发冲突。
2. 校对回执里的工具及来源修订、参数摘要与检查点。对输出中契约声明的订单、时间、资源等范围字段进行比对。参数摘要验证的是宿主提交的对应关系，宿主执行的独立证据仍以真实工具或服务端记录为准。
3. 校验输出 Schema、结果大小、同运行且有效的证据引用。按发布时配置的业务规则解释查询成功、零行、失败、未核验和按流程跳过。保存回执、节点状态与事件后再推进下游。

| 情况 | 运行详情中的反馈与下一步 |
| --- | --- |
| 正常查询并返回空集合 | 「查询成功 · 0 行」。接收回执并按版本继续。 |
| 当前 Codex 会话无工具或授权明确失效 | 「等待恢复 Codex 工具／授权」。回执记录已知失败阶段；明确未执行时恢复条件后在同个运行继续。 |
| 回执格式错误 | 显示字段路径、期望类型和实际类型。用已捕获的真实结果修正封装后提交。实际工具契约变化则提示更新草稿与重新发布。 |
| 提交回执时断线 | 用原报文、原幂等键再次提交。已接收时返回原回执和推进结果。 |
| 发出工具请求后失联，结果未知 | 标记「调用结果未知」，保留已知执行记录并暂停自动推进。 |
| 流程分支主动跳过查询 | 「按流程跳过」，保留所走分支与原因。 |

若允许多个 Codex 会话接力同一运行，需在业务工具调用前增加独占认领。建议在现有 `workflow_advance` 中增加兼容的认领提交类型，以事务绑定检查点、认领方和当前修订，新版严格节点凭认领有效信息提交结果。认领用于控制宿主派发次数，结果提交幂等用于控制推进次数。认领之后失联时按可能已调用处理，复用恢复机制查看同一运行。旧版节点和旧客户端沿用原协议。

## 五、分批开发与验收

| 批次 | 改动 | 相应验收 |
| --- | --- | --- |
| 发现和添加节点 | 宿主目录优先、状态按所选执行方式投影、工具入口统一 | 已配置且有契约的 Codex MCP 能直接添加为宿主节点。只存在目录信息、宿主不可用、同名来源冲突时，各有准确提示。正常宿主路径不会误触发直连登记或检测。 |
| 传参与回执 | 统一映射展示、检查点精简返回、结构化验证、接力诊断 | 从日志输出传递字符串 `traceId`。错类型、缺失、分支不保证和环境越界被拦截。覆盖零行、权限失效、Schema 变化、重复提交、调用结果未知；并发接力交付时验证同一检查点只有一个有效认领。 |
| 独立运行入口 | 显式启用直连、复用已登记连接、验证并选择执行方式 | 同一工具可在草稿显式改用合适的直连绑定。检查已选及可达节点的执行依赖。包含任何宿主节点时明确列出待接力节点。仅使用直连和可独立执行步骤的试点可脱离 Codex 运行。 |

首轮使用隔离数据目录和合成 MCP 跑通「发现 → 新建节点 → 映射 → 发布 → 接力 → 归档」。真实 Codex 宿主验证、公司权限与 Win10 验收以各自执行证据记录。历史运行仍按原发布快照和原回执读取。

## 六、本地实施记录

- Web 默认读取 `host_catalog`。旧调用方仍可显式选择 `catalog`，沿用原来的目录探测行为。新增宿主节点使用结构化回执，已有节点按其版本执行。MCP 工具名称和数量保持兼容。
- 在 macOS arm64 上使用本机 Codex `0.169.0-alpha.11.1`、隔离的 Codex Home 和合成 MCP。宿主目录同步后无 FlowHub 直连记录。发布后日志工具生成 `trace_demo_0042`，核对工具收到相同值并返回 0 行。两次宿主调用的结果都进入报告证据，Markdown 和 HTML 均完成归档。
- 按单个服务启用并检测直连，完成独立环境绑定验证后，把同源节点切换到直连。发布后由 FlowHub 完成调用，运行无需 Codex 接力。宿主和直连测试均使用合成数据。
- 桌面浏览器覆盖从发现页进入草稿、插入工具、保存字段映射、启用直连与导入绑定。回执回归覆盖独占认领、幂等重放、修订与参数摘要不匹配、输出契约、范围校验、恢复授权与结果未知。
- 真实企业 MCP、企业权限、真实模型自主接力和 Windows 10 尚未验证。可重复执行的本机协议验收入口见 [smoke-codex-host-handoff.mjs](../../../scripts/smoke-codex-host-handoff.mjs)。

## 七、复审记录

本轮审计以 `1c15925` 为基线，重验发现、编排、接力回执和独立直连。

- 目录读取失败、明确需要授权或同名来源不明确时，旧目录保留供查看，相关工具暂停添加。单独登记和检测 FlowHub 直连时仍可使用有效的 Codex 目录。
- 切换执行方式核对所选绑定的工具修订、连接来源和环境。连接地址、启动配置或认证引用变化后，需要重新确认直连来源。切换和撤销后根据当前草稿重新计算 Codex 依赖。
- 节点属性支持本地 Schema 引用字段、样例和回执范围比对。删除参数映射时清除对应的无效输入状态。回执范围按 JSON 类型验证，结果和证据引用分别校验。
- 已结束或过期的认领无法再发放凭证。运行详情区分宿主回报与 FlowHub 记录的本地状态。已接收的回执仍可用原请求幂等取回，确认失联后的未知结果不自动推进。
