# FlowHub 2.0 本地使用说明

## 打开本机工作区

打开 [本机 FlowHub](http://127.0.0.1:18473/) 即可进入。使用模型 Key 或 MCP 凭据时，首次在「系统设置 → 配置与凭据库」设置 12–256 个字符的独立口令，之后使用该口令解锁。升级后可用旧凭据库口令解锁，原凭据和 Key 引用继续有效。

FlowHub 的管理页信任能访问本机回环端口的进程。本机地址适合单用户使用，避免通过代理或转发供其他设备访问。浏览器自动建立同源管理会话，写请求仍校验 CSRF。会话恢复时保留当前页面和未保存内容，写操作由用户重新发起。

## 导航与页面入口

侧栏使用三个分组、七个直达入口，所有菜单同级：

| 分组 | 入口与用途 |
| --- | --- |
| 工作区 | 工作流：创建、编辑、发布与启动；运行记录：进度、结果与报告 |
| 能力与连接 | 能力发现：Codex 的 MCP、Skills、插件与关系；MCP 服务：连接配置和工具目录；环境与资源：固定环境、资源范围与工具权限 |
| 系统配置 | 模型设置：模型服务与 Key；系统设置：宿主接入、配置与凭据、数据备份及诊断 |

原有 `/workflows`、`/runs`、`/discovery`、`/connections`、`/bindings`、`/models`、`/settings` 地址保持兼容。进入工作流的编排画布时，侧栏仍选中“工作流”，可从顶部面包屑返回。

窄屏点击顶部“打开导航”显示抽屉；选择入口后收起，关闭按钮、Esc 或点击遮罩均可关闭。抽屉打开时背景暂停交互、Tab 留在菜单中；关闭后焦点返回打开按钮。放大窗口后恢复常驻侧栏。页面放大或平移时，抽屉跟随实际可视区域，导航列表可在剩余空间内滚动。未保存草稿的离开提示继续生效，取消离开时抽屉和填写内容均保留。

## 发现与导入

Codex 能力发现页首次扫描本机上下文，后续优先读取完成快照。可选择自动查找、手动填写 Codex 绝对路径，或仅导入配置；仅配置模式不启动 CLI/App Server，来源覆盖不完整时显示“部分完成”，未知不等于0。页面记住当前上下文。“重新扫描”读取配置。“同步 Codex 工具目录”让独立的本机 Codex App Server 读取当前上下文的工具定义及可获得的授权状态。读取目录可能初始化已配置的服务，实际业务工具在运行时由当前接力会话调用。
插件已安装、已启用、Schema 已发现及可执行是独立状态。多版本安装歧义、配置损坏、缺少认证都显示部分结果；不要把空清单当作已完整扫描。

本地市场目录中的候选会单独显示“可用，尚未安装”，不计入“已安装插件”。读取范围为当前已登记用户目录的个人市场及可信项目市场；只读取目录介绍，不跟随候选源码路径、不下载或安装插件、不读取其 MCP/Skill、更不运行 hooks。安装策略为 NOT_AVAILABLE 的候选显示不可用，不计入可用数；未知格式或越出登记根目录的链接明确报部分完成。来源格式依据 [OpenAI 官方插件目录说明](https://developers.openai.com/plugins/build/plugins#marketplace-metadata)。
个人与项目中同名市场/插件的介绍或策略不一致时，显示“市场来源冲突”并列出各来源，不猜哪份生效；未安装候选不计入可用数。已有安装、启用和连接绑定事实保持，市场元数据不会擅自停用它们。

页面分为 MCP 服务、Skills 技能、插件与关系、需处理。每项显示用途、来源及使用位置；MCP 详情中查看真实工具与参数，Skill 详情中查看声明依赖和依据。同一插件的 Skill 不自动归属于其 MCP；独立技能无需声明 MCP 依赖。未在本次扫描确认的旧来源移到“需处理”，保留旧资料，不能导入。

“需处理”显示目录未同步、来源失效、同名冲突、明确的 Codex 授权问题，以及已设置直连的连接问题。目录读取不完整时，可保留上一次的资料并检查发现设置。在 Codex 恢复 MCP 授权后，同步目录以更新状态。

具名工具的输入和输出契约均可用时，点“用 Codex 添加到流程”，选择 v2 草稿和插入位置。画布中的“已发现能力”默认显示所选 Codex 上下文的能力。添加宿主节点会把自动模式的草稿改为接力模式。

流程需要独立运行时，在该服务详情点“启用 FlowHub 直连”。受支持的配置进入本机表单，其他启动或认证方式可在“MCP 服务”登记。检测工具目录后，可用“用直连添加到流程”选择草稿和环境绑定。多个同源绑定需要明确选择。画布允许在同一来源、工具和契约之间切换执行位置，已有参数映射会保留；带有特定范围限制的节点需要重新审阅配置。

中文说明由 Codex 在同步时通过现有 `host_scan(action=submit_descriptions)` 提交；网页不另调模型、不自动启动 Codex。可从“中文整理方式”复制任务给当前 Codex 会话。支持中文用途与原名检索、原文切换、手工修正。来源更新后译文标为待更新，自动整理不会覆盖手工文案。工具名、参数键、Schema、原始 `SKILL.md` 和业务数据保持原值。契约见[中文说明同步](DISCOVERY_LOCALIZATION.md)。
导入只写 FlowHub，源 Codex 配置不变。相对命令需要在 MCP 服务补充绝对路径。需要独立连接的服务先点“启用 FlowHub 直连”，表单按普通配置、认证凭据、用途待确认分组。普通配置用文本填写；认证凭据使用隐藏输入；未知变量需按服务说明确认用途，仍按敏感值保护。每项可选择“使用来源已有配置（加密保存）”、填写新值或已有引用；来源原值不会回显。只有专用本地管理入口可读取并加密导入来源值，不复制 Codex OAuth，其他认证头暂报 CREDENTIAL_IMPORT_UNSUPPORTED。托管插件和 Skill 使用 codex_host，由宿主执行。

“保存配置”将本次新建项和连接引用一并保存，任一项失败均不留下半套配置。“保存并检测连接”在保存后仅检测当前服务的协议及工具目录，不执行业务工具、不验证资源绑定；失败时配置已保留，可直接“重试检测”。来源或上下文发生变化会拒绝旧版本提交，并保留填写内容。凭据库锁定时可在表单内解锁，已有填写不会丢失。

## 配置与凭据库

“系统设置 → 配置与凭据库 → 新增配置或凭据”提供明确的新增入口，可登记 MCP 认证凭据、MCP 普通配置，或暂不确定用途的项。库中可按 MCP 认证、MCP 配置、模型 Key、用途待确认筛选，并查看真实使用位置；仅显示名称、类型和引用，不回显保存值。模型 Key 仍通过模型设置登记，不能在 MCP 连接中选择。所有类型的值均在本机加密保存；普通配置不会被当作认证口令处理。

旧项保留原 ID 和加密内容；实际模型及连接引用用于补充用途显示，不按历史名称猜测。用途不确定的项保持待确认。`codebase-memory-mcp` 的 `CBM_ALLOWED_ROOT`（目录范围）与 `CBM_LOG_LEVEL`（日志级别）按该项目公开配置说明显示为普通配置，表单提供说明和原文链接；其他未知环境变量不会自动归类。

## 草稿与固定环境

工作流卡片左下方提供“删除”。确认框会显示名称和 ID；取消不会修改数据。删除将其从工作流库移除，并禁止继续编辑、发布和新启动；历史运行、报告、发布快照、连接和凭据保留，不会一起清空。未发布草稿与已发布工作流都可删除，内置模拟样例删除后也不会因重启重新出现。

确认前可以取消。删除请求提交后，确认框会保持“处理中”并保护焦点；网络失败时保留原请求，点击重试可查询或完成同一次删除。删除后的编辑页持续显示状态和“查看并复制本地 DSL”；DSL 包含已应用配置，未完成的 JSON 文本须从原输入框另行复制。

有运行、自测或助手任务进行中时，先在相应页面结束或取消任务，再删除。确认期间草稿或布局被修改会拒绝删除；关闭确认框、刷新列表、核对新内容后重试。另一窗口删除当前编辑流程时，未保存内容仍留在画布，可通过“查看 DSL”复制，保存与发布会停止。已删除 ID 不可重新导入；需要重新创建时使用新 ID。删除由本地管理员操作，不增加 MCP 工具或助手自主删除权限。

流程编排是工作流的编辑子页面。先进入侧栏“工作流”，通过“新建工作流”或指定卡片的“打开编排”进入画布；侧栏不再单列编排入口，也不自动选择第一个样例。画布顶部“工作流”链接可返回列表，未保存修改仍会提示。带工作流编号的原编辑地址保持兼容，单独的 `/editor` 返回工作流。

先创建草稿，再通过语义操作编辑、校验、生成用例和发布。创建、发布、启动是独立意图；明确请求连续完成时可依次调用，无人工审批节点。
排查模板来自随包固定模板，创建时清空连接绑定、工具保持未配置；不会复制其他用户修改过或已经删除的样例草稿。历史运行页中的助手按该次运行保存的不可变快照解释结果，后来的草稿编辑或删除不会替换历史定义。
生产 production、试运行 staging、测试 test 的绑定不能混用。试运行数据库绑定先登记实际连接、锁定资源，再通过明确的只读合成探测及独立服务权限确认；协议目录同步不等于环境已经验证。
只支持串行与互斥条件，不支持循环、并行或任意脚本。业务内容保持原值，连接认证值仅通过凭据库引用。

## Codex 编排

默认个人入口提供固定 21 工具。旧受限 execution 身份仍提供七个运行工具；显式 authoring 身份可创建并使用自己的新流程，不能取得未授权的旧流程。
发现上下文通过本机管理 API 登记，host_scan 只接受已登记 contextId；不接受任意命令或扫描全盘。
创建链路：capability_search/get → capability_import → workflow_draft_create/patch → workflow_draft_validate → workflow_test_generate/run/status → workflow_draft_publish。
运行链路沿用 `workflow_search`、`workflow_get`、`workflow_start`、`workflow_status`、`workflow_advance`、`workflow_cancel` 和 `artifact_read`。

- 参数映射支持工作流输入、必经的上游节点输出和固定 JSON 值。保存草稿后查看待修正的字段，发布前核对必填、类型、分支可达性和锁定资源。
- 新版具名宿主节点先用 `workflow_status(view="checkpoint")` 读取当前工具、参数和契约，再用 `workflow_advance` 认领检查点。当前接力会话把 `resolvedArguments` 原样传给冻结工具。
- 回执关联认领、检查点修订、工具修订和参数摘要。FlowHub 校验结果 Schema、节点声明的范围字段和字节预算。通过 `submission.evidenceRefs` 关联本次运行的已有证据。`submission.payload` 保存工具返回的业务字段。
- 运行详情区分「Codex 回报」「FlowHub 已记录调用」与 FlowHub 记录的认领过期等本地状态。工具错误可通过 `submission.errorMessage` 提交诊断，凭据内容经过过滤后作为附件保存。
- 当前工具或授权不可用且请求尚未发出时，恢复条件后可继续同一运行。回执传输异常时重发原报文与幂等键。认领过期或业务工具调用结果未知时，停止自动推进，并对照工具审计记录。旧节点仍接受原来的提交格式。

## 用例生成与自测

workflow_test_generate(strategy=deterministic) 根据输入 Schema 产生基准用例；agent_proposed 接收 Codex 提供的合成 Fixture 和断言，不需要模型 Key。
内置聊天助手也可设计用例，再通过同一 agent_proposed 入口提交。自测面板还可选择“AI 辅助生成”，明确选择已有模型配置后发送；MCP 对应 strategy=ai_assisted，必须提供 modelProfileId，可携带 expectedModelRevision。返回 generationId/testRunId 是已接受的生成任务，不代表自测通过；通过 workflow_test_status 或 GET /api/v2/test-runs/:id 查询，SUCCEEDED 后才有 suiteId。套件保留 generatedBy=ai_assisted 和生成来源，用例仍需独立运行与断言。未配Key不影响前两种生成方式。
确定性生成覆盖必填/类型、数字与字符串/数组边界、枚举和布尔输入；布尔分支可独立统计true/false。复杂pattern等无法由采样器满足时返回INPUT_SAMPLE_REQUIRED，需补合法Schema example；超出200例或过大边界报告GENERATION_LIMIT，不承诺自动穷尽。Mock入参和输出也校验已发现Schema。
workflow_test_run 默认 mock；在隔离库通过同一引擎与注入连接器执行，不读取真实 Secret、不连接真实业务服务。缺 Fixture 为 FIXTURE_MISSING/未覆盖；断言失败显示 expected/actual。修改草稿、能力或 Fixture 后旧基线显示 stale，需要重新生成/运行。
自测面板默认 Mock，切换验证级别不会自动发送请求。支持三种明确级别：

- Mock：隔离数据流、夹具与断言，不读取真实凭据或调用真实业务服务。
- Contract：明确选择当前流程引用的绑定和预算，仅经官方 SDK 协商、读取工具目录、比对已冻结 Schema。不执行 tools/call、不运行业务断言、不改变绑定验证状态；协议检查成功不代表业务运行成功。
- Live：明确选择当前流程引用的绑定、套件用例及固定输入，提交 allowedBindingIds、inputScope 和 budgets。inputScope 包含 fixtureHash 和 caseInputs（caseId/inputs），必须与选中的已保存用例完全一致；maxCalls 为全任务工具调用上限（1–50），timeoutMs 为任务时限（1000–60000 ms）。执行仍在隔离运行库内使用同一引擎，但经已登记连接真实调用所选 MCP，不复制凭据到测试库。草稿、权限、绑定、连接或能力变化会阻止后续派发。

Live 的 analysis 夹具只证明数据流，结果标记 AGENT_EXECUTION_UNVERIFIED；host-only 节点不会由夹具冒充真实宿主。调用合成绑定会明确保留 syntheticBindings，不能当企业验收。真实生产只读仍依赖服务端权限，不以工具 annotations 或本机哈希替代。

面板可取消生成或执行任务，管理接口为 POST /api/v2/test-runs/:id/cancel。已派发的远端调用可能仍在执行；outcomeUnknown 表示结果未知，不能把本地 CANCELLED 理解为远端已撤销，也不会自动重放。服务重启后未完成任务标为 INTERRUPTED。丢失接受回执时保留原幂等请求，重试不会产生第二次模型调用、套件或真实工具调用。

生成只调用明确选择的模型，限单轮、64 KiB 上下文、512 KiB 提案及模型配置的超时；不派发模型提出的其他工具。聊天中的普通“自测”只运行 Mock，不能由模型自行填范围升级为 Contract/Live；需要这两级时从面板显式选择，或从 MCP 提交带完整范围的请求。实际工具调用数和目录检查数分别展示；未完整计量的网络或凭据读取数显示未知，不写成 0。

AI 辅助生成仅发送一次实际 HTTP 请求；遇限流或错误保留失败任务，不在这一轮内暗中重试。模型上下文和解码后的提案若包含本地 Vault 中受管认证值，整轮拒绝，不自动脱敏或替换业务原值。凭据库锁定时应先解锁。生成成功不等于断言通过。

编辑套件保留初始 `generationSource`、最近一次 AI `generationRef` 和逐修订 `revisionSources`，`generatedBy` 表示当前修订的提交方式。旧套件在后续编辑时补齐可知来源，不猜已经丢失的历史。node_state、output_equals、argument_equals 必须指定现有节点；工具断言指定节点时须为 MCP 节点。不存在的输出/参数路径是未能求值的失败断言，不能与真实 JSON null 混为一谈。旧套件若含此类无效断言会在运行前拒绝，需明确编辑修复，不自动改写存量数据。

Live 调用已派发但结果未知时，本轮立即停止后续用例；剩余用例显示 NOT_RUN，未知调用不能通过预期错误断言变成绿色成功。收到 MCP 明确错误响应属于已知失败，可以用于预期错误测试。重放同一任务或重启不会再次发送未知调用。

面板等待生成套件回执时保持编辑锁定。存在未保存夹具时，新套件或外部更新只提示，不覆盖输入；可查看更新并暂存原草稿，再按原修订恢复，保存仍受 CAS 保护。终态结果定期只读刷新，切回窗口也刷新；发现基线变化会标为过期，不会自动运行。Mock 的工具轨迹数标为“模拟工具调用”，不当作真实网络调用。

## 常见错误

TYPE_MISMATCH：映射来源与目标 Schema 类型不一致，检查节点、目标 JSON Pointer 及来源字段。
MAPPING_INVALID：目标 Pointer 不合法、字段重叠或必填参数缺失，读取校验 issues 后局部修复。
REVISION_CONFLICT：Web 与 AI 基于旧 revision 同时编辑，保留本地改动，重新读取后合并，不能整图覆盖。
CAPABILITY_STALE：工具 Schema、来源或能力修订改变，读取新定义并修复草稿；旧发布版本不会自动更新。
CREDENTIALS_REQUIRED：连接配置尚未补齐；请打开该服务的“连接配置”，不要把 Key 或口令放入聊天或 MCP 工具参数。
FIXTURE_MISSING：自测尚无节点合成结果，不代表实际服务为空或正常。

## 网页助手与模型

服务重启后，本机凭据库默认锁定，Key 仍加密保留。模型设置与助手会显示实际锁定状态，可直接点击“解锁凭据库”，在本机口令框中解锁；不需要重新填写 API Key。解锁不会自动发送问题或执行工具，已有输入会保留。未产生正文和工具回执的锁定失败轮次可用“重新提问”填回原问题，再明确发送；已有工具回执的轮次继续采用只读续答。探测 passed/failed 是上次测试的历史记录，不代表当前连接或锁定状态。

模型设置先选择“OpenAI（ChatGPT）”服务，Base URL 自动使用 `https://api.openai.com/v1`，默认 Responses 协议。填写 API Key，或编辑已有配置并留空保留原 Key，点击“刷新可用模型”，再从当前 Key 的官方目录下拉选择 Model。支持搜索，已过停用日期的模型不可选；切换服务或修改 Key 后须重新查询，避免沿用其他目录。
选中模型后自动读取该模型的官方文档，显示上下文窗口、最大输入/输出与推理强度，附来源和获取时间。未公开、无法解析或查询失败的参数显示未知，不猜测别名或使用硬编码模型列表。模型目录只证明当前 Key 返回了该标识，工具、流式等能力仍通过“测试文本 / 工具 / 流式”实测；该按钮会发送少量真实模型请求。
已有兼容服务可选择“自定义 OpenAI 兼容服务”，查询其 `/models` 目录，也可明确切换为手工模型名称。完整 `/responses` 或 `/chat/completions` 地址会归一化为 Base URL，再按当前协议使用正确端点，避免路径重复拼接。换服务 origin 时需重新填写对应 Key，不把已有 Key 发给新地址。
Key 只在专用输入保存至本机 Vault。无 Key 时仍可用发现、手工画布、Codex 和 Mock 自测。更换 Key 不会回显原值，不使用浏览器 localStorage 保存 Key。
若探测已明确“不支持工具调用”，普通问答会使用纯文本请求，编排仍明确拒绝执行。认证失败或无法分类的请求错误不会触发这种回退；只按已确认的模型能力处理。
各页面侧边的助手图标打开同一个聊天窗，按“用户提问 → 助手回复”连续排列。Enter发送，Shift+Enter换行，中文输入法组字期间不发送。收起、切页不会取消任务或丢失未发送输入，刷新后可恢复已保存的消息、任务状态与流式片段。标题栏提供历史、新会话、放大与收起；历史菜单支持删除当前会话。
侧栏不再设置单独的 AI 工作台页面；旧 `/assistant` 地址兼容转到工作流并打开悬浮聊天窗，复用原有会话。
助手图标可按住拖动（鼠标、触屏均可），松手吸附到较近的左侧或右侧，并记住高度。点击图标旁的小箭头可贴边收起，只留22像素的边缘标签；标签上半部分直接打开聊天，下半部分箭头恢复完整图标。聊天窗跟随图标的左右位置。键盘聚焦图标后，用上下键调高度、左右键切边，Esc贴边收起；调整位置不发送消息、不取消任务。位置和收起状态只保存在当前浏览器的本地偏好中，刷新后恢复；窗口或手机可视区域缩小时自动保持入口可见。
不再手动选择帮助/编排模式：只解释、给方案、建议等请求仅只读；明确修改、保存、自测、发布或运行时才提供对应动作。否定、疑问或引用中的动作不构成授权。每轮回复下方可展开真实工具活动、资料引用、来源与诊断，JSON和内部ID默认折叠，正文支持安全Markdown。模型输出的HTML不会执行。
询问当前MCP时，助手优先读取已登记连接、缓存工具名称、发现来源及扫描状态，区分未扫描、部分、失败与已确认空目录。缓存不代表实时宿主清单；FlowHub自己的固定21工具不冒充用户MCP。目录摘要不包含连接地址、参数或凭据，也不会为列清单执行一次业务工具。
上下文标签显示当前页面、所选流程/节点或运行；在运行页查看的选中证据随本轮附带，每份最多前16000 bytes，完整内容仍保留。可移除标签，或在标签详情从实际列表选择关联流程/运行，无需手填ID。同来源、同模型的近期对话才会随新请求发送，切换选择不会默认外发其他运行历史；旧消息仍可在本机阅读。
发送回执丢失时，先读取已接受任务，再用原幂等键重试同一请求。停止、断线或服务重启会保留已输出正文与工具回执；“继续回复”只解释已有结果，不重复原写操作。模型可配置超时、流式和轮数/用量预算，缺少usage显示未知。聊天中的完成声明不是保存证据，应以本轮实际工具回执为准。
MODEL_AUTH_FAILED 表示认证失败，MODEL_RATE_LIMITED 表示429；保留会话，不无限重试。MODEL_UNSUPPORTED_TOOLS 表示仅文本模型，仍可问答。取消停止后续动作，已经完成的工具回执会保留。重启的未完成任务为 INTERRUPTED，不自动重放写操作。

## 当前画布与撤销

网页整图保存同时检查语义修订与布局修订；并发的 MCP 拖动即使尚未通过事件送达，也不会被旧画布覆盖。遇到布局冲突时本地输入保留，先重新合并；同一位置字段可选择本地或服务端值，再保存。管理 API 的 draft PUT 使用 If-Match 和 expectedLayoutRevision；旧 v1 调用只改语义且布局与服务端完全相同时可省略布局修订。

没有公布 outputSchema 的 MCP 工具选择 text 适配器后，后续节点可引用 /text，或将整个 {text, content} 结果传入结束节点。画布和发布校验使用同一固定输出契约；原始协议回执完整保留。此时即使工具附带无契约的 structuredContent，映射仍使用明确选择的文本信封；已经公布的结构化输出契约继续校验，不凭文本猜测 JSON。

在画布工具栏或节点属性区点击“AI 助手”，唤起同一个全局聊天窗，自动关联当前流程和选中节点。AI改图由服务端真实保存，刷新后仍存在。未保存输入和发布审阅候选保持不变；不同节点、字段和布局的并发修改自动合并，同一字段冲突分别展示双方值，可逐项选择保留本地或采用服务端版本后按新 revision 保存。
每轮改图回复提供“查看改动”和“撤销改图 / 重做改图”，只逆转该动作涉及的字段；后来同字段已修改时返回 REVISION_CONFLICT，其他编辑保持不变。新节点仅局部布局，不重排整张画布。
自测面板可生成、编辑Fixture、运行Mock并查看expected/actual。通过后修改草稿会提示基线过期。
运行的 analysis 检查点可选择已配置模型继续，使用独占租约和同一推进接口；host_tool/host_skill 或明确 codex_host 节点须由Codex执行，Key不能替代宿主权限。

## 数据保留与历史消息

“系统设置 → 数据保留与清理”先显示对象与数量，再确认绑定该范围的预览哈希。终态运行、助手与自测结果正文保留 7 天，元数据保留 30 天；结果来源先到期时，关联任务、消息、工具回执和应用事件中的副本也随之到期。活跃运行、活跃助手会话、已保存的测试套件配置、发布版本与能力修订不参与这次正文清理。预览本身不修改数据；提交时范围或正文发生变化必须重新预览。

新助手消息保存 taskId 和上下文、模型来源，保留策略可区分同一会话中的不同来源。已交付旧版消息可能没有 taskId，无法证明其正文与同会话已到期任务无关。这类消息在会话存在到期或待删除任务时，单独列入“来源到期会话中的历史未归属消息正文”范围，显示数量与消息 ID，即使消息创建时间较新。只有管理员确认本次清理后才清除正文并标记 resultsExpiredAt；不会猜测内容归属、替换字段或自动执行清理。活跃会话继续受保护，具有任务归属且来源无关的较新消息保留。

该兼容策略只处理可确认的来源关联及明确列出的未归属旧消息，不声称能恢复旧版本未记录的模型派生链路。已有备份、历史 WAL 和外部复制件具有独立生命周期；清理不宣称对这些副本安全擦除。

## 上下文、限额与宿主验收

发现页可登记自定义 Codex Home、项目目录和 Profile，并明确是否读取可信项目或独立 App Server 会话；读取选项更新使用 revision CAS。独立会话目录不能代表桌面会话已有授权。
原生 host_tool 支持有边界的本地 $defs/$ref 和对象 additionalProperties 默认语义；远程引用、递归和超预算 Schema 明确拒绝。检查点仍按冻结的原始宿主契约验证，Mock 明确标记 synthetic_fixture，不能作为真实宿主已执行的证明。
v2 MCP 节点可显式配置 rowLimitArgument（例如 /limit）为下游 Schema 的数字型原生参数，执行前取用户值、工作流预算、绑定预算的最小值。未声明时 TOOL_LIMIT_ENFORCEMENT 事件记录 unsupported；返回结果行数检查不能保证远端查询成本受限。
可在构建服务端后运行 `node scripts/smoke-codex-host-handoff.mjs`，用本机 Codex 与隔离的合成服务核对发现、跨节点映射、认领、回执、报告归档及独立直连。

开发者可运行 npm run test:codex-local；它使用临时 CODEX_HOME、合成库与独立 daemon，通过当前本机 Codex App Server 完成真实 MCP 编排/自测/报告闭环，不读取已有登录凭据，不调用付费模型。30 个自然语言真实模型场景需另行配置模型后验收，协议测试通过不代表模型效果已验收。


## 发现与助手的并发边界（2026-10-31）

更新发现上下文时针对当前 `contextId` 和 `expectedRevision` 做比较；修改 Home、CWD、Profile 或 CLI 版本而形成另一身份时，页面保留输入并提示登记新上下文，不会改写另一条记录。清空 Profile 表示默认 Profile；自动模式清空 CLI 路径表示重新自动查找。API 省略字段保留当前值，显式 `codexPath: null` 仍表示仅配置模式。

编辑中文说明时冻结开始编辑的来源、上下文及显示修订。重新扫描、关闭再打开详情不会悄悄刷新草稿基线；发生冲突后保留草稿，由用户取消编辑并重新开始以采用新基线。凭据引用保存同样检查提交时的来源与上下文版本；旧扫描结果应先重新扫描。

“继续回复”绑定被点击的具体任务和原上下文，只解释已有结果。只读状态回执不会显示“已保存”或改图操作；只有实际草稿写回执显示修订和查看改动。明确的输入拒绝允许修改后重新提交，网络结果不确定时保留原请求键以避免重复写入。大目录会先保留所选流程、运行和节点，再按 UTF-8 字节预算裁减目录及帮助片段。

悬浮聊天窗随可视区缩放、平移和低高度变化调整，发送区保持在当前可视范围；位置仍可拖动、贴边收起并恢复。
